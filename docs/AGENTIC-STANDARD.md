# Changing a workflow

Start at the README task table. Follow the route as a new adopter would.
Keep the purpose, authority, current work and required check within two links.
Give each rule one home. Put exact project commands and grants in the adopter's repository.

Before removing a step or a tool, inspect its imports, dynamic paths, CLI calls, examples and tests.
Preserve the current consumer's behavior and failure handling unless the change explicitly replaces them.

Walk one real task through the revised instructions. Exercise a failure and recovery.
Check the actual output before reporting success. Count the required reading and cut repeated instructions.
Report what changed, what you checked and any remaining limit.
