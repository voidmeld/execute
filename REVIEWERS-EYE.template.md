# Reviewer's eye

Use the lane names from this project. Under each one, keep the few questions that
help a reviewer judge how well the change serves its users. Point each question to
its shelf entry so a reviewer can check the evidence and its limits.

## [Review lane type]

- [ ] When [user in a specific situation] tries [action], can they [observable result]?
  Check [what to inspect]. See [shelf entry].

## [QA lane type]

- [ ] Try [representative input or failure] under [conditions]. Look for [visible
  behavior] and record [what actually happened]. See [shelf entry].

Repeat a section for each applicable lane type. Where the project requires
product-neutral checks, describe the task and the behavior in the checklist. Keep
reference names and distinctive wording on the shelf. If a question rests on a
hypothesis, use it to gather evidence before treating the answer as a requirement.
